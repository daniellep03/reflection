# Week 4 Reflection — GoF Structural Patterns

This week we covered the Gang of Four Structural patterns. The one that made the most sense to me was the **Facade** pattern.

The basic idea is pretty simple — instead of letting your code talk directly to a bunch of complicated subsystems, you create one clean interface that handles all of that behind the scenes. It keeps things organized and makes your code way easier to read.

I used this in our sprint when building out the auth part of our REST API. The login route was getting messy — it was directly calling the database, checking the password, and generating a JWT token all in one place. It worked, but it was hard to follow and even harder to change anything without breaking something.

So I pulled all of that logic into an `AuthService` class. Now the route just calls `authService.login()` and gets back a token. It doesn't need to know anything about how that actually happens under the hood.

```js
router.post('/auth/login', async (req, res) => {
  const token = await authService.login(req.body.email, req.body.password);
    res.json({ token });
    });
    ```

    That's the Facade in action — one simple call that hides all the messy details. If we ever swap out how we handle tokens or passwords, we only change it in one place instead of hunting through every route file.

    Honestly this pattern clicked for me more than the others because I've already been running into the problem it solves.
